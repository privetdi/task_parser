# Курсы НБ РБ и графики IEA

Сервис по расписанию собирает официальные курсы валют Нацбанка Беларуси, хранит их в SQLite,
раз в день отправляет Excel-отчёт на почту и (дополнительно) рассылает новые графики каталога IEA.
Есть веб-интерфейс: состояние задач, последние результаты, кнопки ручного запуска.

**Стек:** Python 3.12 · FastAPI · SQLAlchemy · SQLite · APScheduler · Playwright · React + TypeScript (Vite).

## Что делает

| Задача | Что происходит | По умолчанию |
|---|---|---|
| Догрузка истории | Загружает исторические курсы порциями, помнит позицию, продолжает после сбоя или перезапуска | при старте, пока не загружено всё |
| Проверка курсов | Добавляет новые и обновляет изменённые курсы без дублей | ежедневно 08:00 |
| Excel-отчёт | Формирует `.xlsx` с актуальными курсами (у каждой валюты указана дата курса) и шлёт на почту | ежедневно 09:00 |
| Графики IEA | Ищет новые графики на первой странице каталога, делает снимок каждого, шлёт **по одному письму на график**, уже отправленные не повторяет | ежедневно 10:00 |

Время — по Europe/Minsk, меняется настройками (см. ниже).

## Запуск

### Docker (одной командой)

```bash
cp .env.example .env        # при желании поправьте настройки; без файла всё работает по умолчанию
docker compose up --build
```

Интерфейс: <http://localhost:8000>. Данные (база, письма, графики) лежат в `./data`.

### Без Docker

Нужны [uv](https://docs.astral.sh/uv/), Node.js 20+.

```bash
cp .env.example .env
cd frontend && npm install && npm run build && cd ..   # сборка интерфейса
cd backend
uv sync
uv run playwright install chromium                     # браузер для сбора графиков IEA
uv run uvicorn app.main:app
```

Интерфейс: <http://localhost:8000>. Для разработки: `uvicorn app.main:app --reload` в `backend/`
и `npm run dev` в `frontend/` (<http://localhost:5173>, запросы к API проксируются).

## Настройки

Всё задаётся переменными окружения или файлом `.env` — без правки кода. Полный список с пояснениями
и значениями по умолчанию — в [`.env.example`](.env.example). Главное:

| Параметр | Назначение |
|---|---|
| `MAIL_MODE` | `dry-run` (по умолчанию) — письма не отправляются, а сохраняются как `.eml` в `data/outbox/`; `smtp` — реальная отправка |
| `MAIL_FROM`, `MAIL_TO` | отправитель и получатели (через запятую) |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_SECURITY` | SMTP-сервер (`starttls` / `ssl` / `none`) |
| `CRON_RATES_SYNC`, `CRON_RATES_REPORT`, `CRON_IEA_CHARTS` | расписание в формате cron |
| `TIMEZONE` | часовой пояс расписания |
| `BACKFILL_START` | с какой даты грузить историю (по умолчанию 2016-07-01) |
| `IEA_HEADLESS`, `IEA_BROWSER_CHANNEL`, `IEA_PROFILE_DIR` | браузер для IEA: без окна или с окном, Chromium из Playwright или Google Chrome, где хранится профиль (см. следующий раздел) |
| `DATA_DIR` | где лежат база, письма, графики |

Пример для реальной почты (Gmail с паролем приложения):

```env
MAIL_MODE=smtp
MAIL_FROM=me@gmail.com
MAIL_TO=me@gmail.com
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=me@gmail.com
SMTP_PASSWORD=<пароль приложения>
```

## Как проверить, не дожидаясь следующего дня

1. Откройте интерфейс и нажмите «Запустить» у нужной задачи, либо из консоли:
   ```bash
   curl -X POST localhost:8000/api/jobs/rates_sync/run     # проверить курсы
   curl -X POST localhost:8000/api/jobs/rates_report/run   # собрать и отправить Excel
   curl -X POST localhost:8000/api/jobs/iea_charts/run     # собрать графики
   curl localhost:8000/api/runs                            # журнал: что выполнено, что нет и почему
   ```
2. В режиме `dry-run` письма лежат в `data/outbox/*.eml` — их открывает любой почтовый клиент.
3. Реальный SMTP без внешнего ящика: `docker compose --profile mail up` поднимает
   [Mailpit](https://mailpit.axllent.org/) (письма на <http://localhost:8025>); в `.env`
   укажите `MAIL_MODE=smtp`, `SMTP_HOST=mailpit`, `SMTP_PORT=1025`, `SMTP_SECURITY=none`.
4. Срабатывание расписания: поставьте, например, `CRON_RATES_REPORT=*/2 * * * *` и перезапустите.
5. Excel без отправки письма: кнопка «Скачать Excel» в интерфейсе или `GET /api/reports/rates.xlsx`.
6. Тесты: `cd backend && uv run pytest`.

Примеры результатов лежат в [`examples/`](examples/).

## Если сайт IEA показывает проверку

Сайт IEA закрыт проверкой Cloudflare («Verify you are human»). Сервис её автоматически не обходит
(без подмены признаков браузера, решателей и обходных адресов): задача пишет в журнал «сайт отдал
защитную страницу», а остальные задачи работают как обычно. Проверку может пройти владелец —
один раз и сам:

1. Остановите сервис: один профиль браузера нельзя открыть двумя окнами.
2. В каталоге `backend/` выполните `uv run python -m app.sources.iea_login` — откроется окно
   браузера с iea.org.
3. Пройдите проверку. Когда появится каталог графиков, помощник напишет «проверка пройдена» —
   закройте окно.
4. Допуск сохранён в профиле браузера (`IEA_PROFILE_DIR`, по умолчанию `data/browser-profile`).
   Запустите сервис; для регулярных запусков с этим профилем поставьте `IEA_HEADLESS=false`:
   допуск, полученный в окне, в headless-режиме может не приниматься.

Ограничения:

- Срок действия допуска задаёт сайт. Когда он истечёт, в журнале снова появится сообщение с этой
  командой.
- В Docker нет окна, поэтому сбор IEA лучше запускать на хосте.
- Графики рисуются в браузере из данных на странице, поэтому результат — снимок карточки графика
  (PNG), а не исходный файл IEA. На страницах графиков указана лицензия CC BY 4.0: при
  повторном использовании сохраняйте ссылку на источник (она есть в теме и теле письма).

## Как это устроено

Требования к поведению сервиса и сценарии проверки описаны в [`docs/specs/`](docs/specs/).

```
backend/app/
  sources/    внешние системы: nbrb.py (API НБ РБ), iea.py (браузер Playwright, снимок карточки графика),
              iea_login.py (помощник: пройти проверку сайта вручную)
  services/   логика: загрузка курсов, отчёт, графики, почта, учёт отправленного
  jobs/       задачи: реестр, раннер (журнал и изоляция ошибок), планировщик
  api/        HTTP API для интерфейса
frontend/src/ интерфейс (React + TypeScript)
```

Зависимости идут вниз: `api → jobs → services → sources`. Сервисы получают клиентов и сессию
аргументами, поэтому проверяются тестами без сети и без браузера.

Ключевые решения:

- **История порциями по 365 дней.** API НБ РБ молча обрезает ответ `dynamics` до 365 точек (запрос
  на два года вернул один год без ошибки). Период режется на порции встык, после каждой порции
  позиция сохраняется в базе (`currencies.history_loaded_from`) — поэтому загрузка возобновляется
  с того же места. Прогресс виден в интерфейсе.
- **У валюты несколько записей справочника.** USD: `Cur_ID=145` до 2021-07-08 и `431` после (общий
  `Cur_ParentID`). История склеивается по `Cur_ParentID`.
- **Без дублей.** `UNIQUE(валюта, дата)` в базе и атомарный `INSERT … ON CONFLICT DO UPDATE`;
  повторная загрузка не плодит записи, изменённый курс обновляется.
- **Состояние переживает перезапуск.** Курсы, журнал запусков и учёт отправленного — в SQLite.
  Таблица `deliveries` (`UNIQUE(тип, ключ)`) гарантирует, что отчёт за дату и каждый график уходят
  один раз; неудачная отправка повторяется при следующем запуске. Запуски, прерванные остановкой,
  помечаются «прервано».
- **Ошибка одного источника не останавливает остальные.** Каждая задача выполняется отдельно, любое
  исключение превращается в запись журнала со статусом и причиной; сбой одной валюты или одного
  графика не мешает остальным. При остановке сервиса долгие задачи завершаются между порциями.
- **Float вместо Decimal.** Курсы — 4 знака после запятой, сравнение с округлением; для отчёта этого
  достаточно.

## Что не реализовано и что я сделал бы дальше

- **Графики IEA: автоматический сбор на живом сайте не подтверждён.** Сайт закрыт проверкой
  Cloudflare: на машине разработки и headless, и обычный Chromium получают «Verify you are human»
  (Google Chrome не проверялся — не установлен). Обходить проверку я не стал; сервис пишет в журнал
  понятную причину и команду для ручной проверки (см. раздел выше). Что проверено:
  разбор каталога — на архивной копии настоящей страницы (Wayback, 2026-10-02: 12 карточек, настоящие
  заголовки); работа клиента в настоящем Chromium — на подменённых ответах сайта (снимок лениво
  отрисованной карточки, профиль с cookie, защитная страница); дедупликация, одно письмо на график,
  повторы и изоляция ошибок — тестами. Не проверено: отрисовка графиков и снимок на живой странице
  (нужен допуск, который получает владелец), срок действия допуска и принимается ли он в headless.
  Следующий шаг: запросить у IEA разрешённый доступ — API или список разрешённых клиентов
  ([Help centre](https://www.iea.org/help-centre/contacts)).
- **Догонять пропущенные запуски после простоя.** Сейчас пропущенное расписанием не выполняется
  задним числом (задачи идемпотентны, есть ручной запуск; окно проверки курсов само удлиняется до
  последней сохранённой даты, поэтому в данных дыр не остаётся).
- **Миграции Alembic** вместо `create_all`, если схема будет меняться.
- **Decimal** для курсов, если понадобится точная арифметика.
- **Авторизация** интерфейса и API — сейчас сервис рассчитан на запуск в доверенной сети.
- **Графики динамики курсов** в интерфейсе и метрики/алерты по сбоям задач.
