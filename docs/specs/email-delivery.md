# Spec Delta

## Purpose

Единый способ отправки писем с вложениями: реальный SMTP либо режим без реальной отправки для проверки; отправитель, получатели и параметры сервера задаются настройками.

## ADDED Requirements

### Requirement: Параметры почты из настроек
Сервис SHALL брать адрес отправителя, список получателей, параметры SMTP-сервера (хост, порт, логин, пароль, шифрование) и выбор режима отправки из настроек окружения без изменения исходного кода.

#### Scenario: Несколько получателей
- **WHEN** в настройках указано несколько адресов получателей
- **THEN** письмо адресуется всем указанным получателям

#### Scenario: Секреты не в коде
- **WHEN** репозиторий публикуется
- **THEN** в нём нет паролей и реальных адресов, есть только файл-образец настроек

### Requirement: Режим без реальной отправки
В режиме «без реальной отправки» сервис SHALL собирать письмо полностью (тема, получатели, вложения) и сохранять его как `.eml` в настраиваемый каталог, не обращаясь к SMTP-серверу; этот режим SHALL быть включён по умолчанию.

#### Scenario: Проверка без почтового сервера
- **WHEN** режим без реальной отправки включён и задача отправляет отчёт
- **THEN** в каталоге появляется `.eml`-файл с вложением, который открывается в почтовом клиенте, сетевых обращений к SMTP нет, а отправка учитывается как выполненная

### Requirement: Отправка по SMTP
В режиме SMTP сервис SHALL отправлять письмо через заданный сервер и считать отправку выполненной только после успешного ответа сервера.

#### Scenario: Сервер отклонил письмо
- **WHEN** SMTP-сервер вернул ошибку (авторизация, недоступность, отказ)
- **THEN** отправка не считается выполненной, ошибка с понятным описанием попадает в журнал запуска

### Requirement: Учёт отправленного
Сервис SHALL хранить в базе факт каждой успешной отправки (вид сообщения, ключ — дата отчёта или идентификатор графика, время, получатели) и число неудачных попыток с последней ошибкой.

#### Scenario: Проверка, что было отправлено
- **WHEN** пользователь смотрит состояние сервиса
- **THEN** видно, какие отчёты и графики отправлены, когда и кому, а какие ожидают повтора из-за ошибки
