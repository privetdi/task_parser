# Spec Delta

## Purpose

Автоматический запуск задач сервиса по расписанию, ручной запуск, журнал запусков, сохранение состояния между перезапусками и изоляция сбоев одной задачи от остальных.

## ADDED Requirements

### Requirement: Набор задач
Сервис SHALL выполнять независимые задачи: догрузка истории курсов, ежедневная проверка курсов, формирование и отправка Excel-отчёта, сбор и отправка графиков IEA.

#### Scenario: Список задач
- **WHEN** сервис запущен
- **THEN** все четыре задачи зарегистрированы, у каждой известны расписание и время следующего запуска (кроме догрузки истории, которая запускается при старте при незавершённости и вручную)

### Requirement: Запуск по расписанию из настроек
Сервис SHALL автоматически запускать задачи по расписанию, заданному настройками окружения в cron-формате и часовом поясе; изменение расписания SHALL NOT требовать правки исходного кода.

#### Scenario: Смена времени отправки
- **WHEN** в настройках изменено время отправки отчёта и сервис перезапущен
- **THEN** следующий запуск происходит в новое время

#### Scenario: Расписание по умолчанию
- **WHEN** настройки расписания не заданы
- **THEN** используются значения по умолчанию, документированные в `.env.example` и README

### Requirement: Ручной запуск
Сервис SHALL позволять запустить любую задачу вручную, не дожидаясь расписания; запуск возвращает управление сразу, а результат становится доступен в журнале.

#### Scenario: Ручной запуск проверки курсов
- **WHEN** пользователь запускает проверку курсов вручную
- **THEN** создаётся запись запуска со статусом «выполняется» и признаком «вручную», по завершении она получает итоговый статус

#### Scenario: Задача уже выполняется
- **WHEN** задача запущена повторно, пока предыдущий запуск не завершён
- **THEN** новый запуск не стартует, пользователь получает понятный отказ «уже выполняется»

### Requirement: Журнал запусков
Сервис SHALL фиксировать каждый запуск задачи: название, способ запуска (по расписанию / вручную / при старте), время начала и конца, статус (выполняется, успешно, частично, ошибка, пропущено, прервано), краткий итог (сколько добавлено / отправлено / пропущено) и описание ошибки.

#### Scenario: Выяснить, что не удалось
- **WHEN** пользователь открывает журнал после сбоя
- **THEN** он видит, какие запуски завершились успешно, какие нет и по какой причине

### Requirement: Изоляция ошибок
Исключение в одной задаче или источнике SHALL NOT останавливать другие задачи и SHALL NOT завершать сервис; ошибка SHALL записываться в журнал.

#### Scenario: IEA недоступен
- **WHEN** задача графиков завершается ошибкой
- **THEN** задачи курсов и отчёта выполняются по расписанию как обычно

#### Scenario: Непредвиденное исключение
- **WHEN** задача выбрасывает неожиданное исключение
- **THEN** запуск получает статус «ошибка» с текстом причины, планировщик продолжает работать

### Requirement: Сохранение состояния между перезапусками
Состояние (загруженные курсы, позиция догрузки, журнал, отправленные отчёты и графики) SHALL храниться в локальной базе SQLite; после перезапуска сервис SHALL продолжать с сохранённого состояния без повторной загрузки и без повторной отправки.

#### Scenario: Перезапуск
- **WHEN** сервис остановлен и запущен снова
- **THEN** курсы, журнал, сведения об отправленном сохранены, незавершённая догрузка истории продолжается

#### Scenario: Запуск, прерванный остановкой
- **WHEN** сервис остановлен во время выполнения задачи
- **THEN** при следующем старте запуск, оставшийся в статусе «выполняется», помечается как прерванный, а не висит бесконечно

### Requirement: Конфигурация через окружение
Параметры почты, получателей, расписания, часового пояса, границы истории и путей к файлам (база, письма, графики, отчёты) SHALL задаваться через переменные окружения или `.env`; для каждой настройки SHALL быть значение по умолчанию либо явное сообщение об отсутствии обязательного параметра.

#### Scenario: Отсутствует обязательная настройка SMTP
- **WHEN** выбран режим SMTP, но хост или получатель не заданы
- **THEN** сервис сообщает, каких настроек не хватает, и не падает на первой отправке с неочевидной ошибкой
